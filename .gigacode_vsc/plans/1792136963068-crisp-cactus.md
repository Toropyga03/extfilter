# План реализации фичи Whitelist (игнорирование ресурсов)

## Обзор

Необходимо добавить возможность создания списка белых ресурсов (IP/URL/домены), которые НЕ должны блокироваться даже если они присутствуют в чёрном списке. Список загружается из файла и поддерживается механизм hot-reload через сигнал HUP.

**Whitelist работает для ВСЕГО:** HTTP доменов, URL, SNI (через tries) И IP адресов (через ACL).

## Архитектурные решения

### 1. Формат файла whitelist

Файл поддерживает тот же формат, что и чёрные списки (domains/urls/hosts):
- Каждая строка — один ресурс
- Строки, начинающиеся с `#` или `;` — комментарии
- Поддерживаются:
  - Домены: `example.com` (точное совпадение)
  - Домены с маской: `*.example.com` (все поддомены)
  - URL: `example.com/path/to/resource`
  - IP адреса IPv4: `192.168.1.1/32` или `192.168.1.1`
  - IP адреса IPv6: `[2001:db8::1]/128` или `[2001:db8::1]`

### 2. Структура данных

#### 2.1. Для HTTP/SNI проверок (tries)
Белый список хранится в двух trie-структурах (аналогично чёрному списку):
- `whitelist_mdomains_trie` — для доменов с маской (*.domain.com)
- `whitelist_urls_trie` — для точных URL и доменов без маски

Использование trie обеспечивает быстрый поиск O(k), где k — длина ключа.

#### 2.2. Для IP проверок (ACL)
Для IP адресов whitelist интегрируется в ACL механизм:
- IP из whitelist НЕ добавляются в ACL контекст как правила для блокировки
- При инициализации ACL проверяем: если IP есть в whitelist → пропускаем его
- Это обеспечивает приоритет whitelist над ACL блокировкой по IP

### 3. Механизм проверки

#### 3.1. Для HTTP/SNI (tries-based)
При проверке ресурса на блокировку:
1. Сначала проверяем whitelist (если ресурс в белом списке → НЕ блокируем)
2. Затем проверяем blacklist (если ресурс в чёрном списке → блокируем)

Это обеспечивает приоритет whitelist над blacklist.

#### 3.2. Для IP (ACL-based)
При построении ACL из файлов hosts/ssl_ips:
- Если IP есть в whitelist → НЕ добавляем его в ACL правила
- Результат: IP из whitelist не будет заблокирован через ACL механизм

## Детали реализации

### 1. Последовательность проверок в checkURLBlocked:
```cpp
int TriesManager::checkURLBlocked(...)
{
    // 1. Проверяем whitelist сначала
    if(whitelist_tries.search_prefix(&_agents[thread_id], rhost, revhost_len, url_buf, buf_len))
    {
        return 0; // В белом списке - не блокируем
    }
    
    // 2. Проверяем blacklist
    if(_bl_manager.getHttpBlacklist()->getActiveTrie()->search_prefix(...))
    {
        return 1; // В чёрном списке - блокируем
    }
    
    return 0; // Не в списках - пропускаем
}
```

### 2. Последовательность проверок в checkSNIBlocked:
```cpp
int TriesManager::checkSNIBlocked(...)
{
    // 1. Проверяем whitelist
    if(whitelist_tries.lookup(&_agents[thread_id], (rptr+1), sni_len, (char *)sni, sni_len))
    {
        return 0; // В белом списке - не блокируем
    }
    
    // 2. Проверяем blacklist
    if(_bl_manager.getSNIBlacklist()->getActiveTrie()->lookup(...))
    {
        return 1; // В чёрном списке - блокируем
    }
    
    return 0;
}
```

### 3. Проверка IP в ACL::initACL():
```cpp
// При парсинге IP из hosts/ssl_ips файлов:
Poco::Net::IPAddress ip_addr(ip);
if(ACL::isIPInWhitelist(ip_addr))
{
    // IP в whitelist - пропускаем, не добавляем в ACL
    _logger.debug("IP %s is in whitelist, skipping", ip);
    continue;
}
// IP не в whitelist - добавляем в ACL как обычно
```

### 4. Загрузка IP из whitelist файла:
```cpp
void ACL::loadWhitelistIPs(const std::string &whitelist_file)
{
    if(whitelist_file.empty())
        return;
    
    std::ifstream wf(whitelist_file);
    std::string line;
    while(std::getline(wf, line))
    {
        // Пропуск комментариев и пустых строк
        if(line.empty() || line[0] == '#' || line[0] == ';')
            continue;
        
        // Парсинг IP с маской: 192.168.1.1/32 или [2001:db8::1]/128
        std::size_t found = line.find('/');
        std::string ip_str;
        if(found != std::string::npos)
        {
            ip_str = line.substr(0, found);
        } else {
            ip_str = line;
        }
        
        // Для IPv6 убираем квадратные скобки
        if(ip_str.front() == '[')
            ip_str.erase(0, 1);
        if(ip_str.back() == ']')
            ip_str.pop_back();
        
        try
        {
            Poco::Net::IPAddress ip(ip_str);
            whitelist_ips.insert(ip.toString());
        }
        catch(...)
        {
            _logger.warning("Invalid IP address in whitelist: %s", line);
        }
    }
}
```

### 5. Hot-reload whitelist:
При получении сигнала HUP:
1. Перезагружаем ACL (с повторной загрузкой whitelist IPs)
2. Перезагружаем blacklist (domains/urls/ssl)
3. **Перезагружаем whitelist** ← новая функциональность
   - `ACL::loadWhitelistIPs(_whitelistFile)` - перезагрузка IP
   - `TriesManager::loadWhitelist(_whitelistFile)` - перезагрузка tries

## Тестирование

### Ручное тестирование (HTTP/SNI):
1. Создать blacklist с доменом `testblock.com`
2. Создать whitelist с доменом `testblock.com`
3. Убедиться, что `testblock.com` НЕ блокируется в HTTP запросах
4. Убедиться, что `testblock.com` НЕ блокируется в HTTPS SNI запросах
5. Добавить в whitelist ещё один домен `allowed.com`
6. Убедиться, что `allowed.com` не блокируется
7. Отправить HUP и убедиться, что whitelist перезагрузился

### Ручное тестирование (IP через ACL):
1. Создать hosts файл с IP `192.168.1.100/32` для блокировки
2. Создать whitelist с IP `192.168.1.100/32`
3. Убедиться, что IP `192.168.1.100` НЕ блокируется через ACL
4. Добавить IPv6 IP в whitelist и убедиться, что он тоже игнорируется

### Проверка формата:
- Пустой файл whitelist → все ресурсы проверяются по blacklist
- Файл только с комментариями → аналогично пустому
- Невалидные строки → игнорируются с предупреждением в лог
- Смешанный формат (домены + IP) → корректно распределяется по tries/ACL

## Риски и ограничения

1. **Память**: 
   - Whitelist дублирует структуру trie (для HTTP/SNI), что увеличивает потребление памяти. Для больших whitelist (100K+ записей) это может быть заметно (~10-20MB на 100K записей).
   - Для IP whitelist использует простой `std::set<std::string>`, что занимает минимум памяти (~100 байт на запись).

2. **Производительность**: 
   - Добавляется одна дополнительная проверка trie для каждого HTTP/SNI запроса. Это минимальная overhead (~10-20ns на запрос).
   - Для IP проверок overhead отсутствует, так как whitelist работает на этапе построения ACL (однократно при загрузке).

3. **Консистентность**: При hot-reload whitelist переключается атомарно (аналогично blacklist с double buffering).

4. **Параллельный доступ**: 
   - Whitelist trie читается из нескольких worker потоков, но не модифицируется во время чтения (используется double buffering при reload).
   - `whitelist_ips` (std::set) модифицируется только в main thread при reload, чтение происходит в ACL::initACL() который тоже вызывается из main thread.

5. **Формат файла**: Смешивание доменов и IP в одном файле требует корректного парсинга. Нужно различать:
   - Домены: `example.com`, `*.example.com`
   - URL: `example.com/path`
   - IPv4: `192.168.1.1/32`
   - IPv6: `[2001:db8::1]/128`
   
   Решение: IP с маской `/32` или `/128` или без маски, но в формате IP → идут в ACL. Остальное → в tries.
